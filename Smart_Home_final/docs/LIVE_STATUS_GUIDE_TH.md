# สอนแก้ Live Status

แก้ไฟล์ `live_status.ps1` ภายใน smart_home1.4 แล้วปิดด้วย Q และเปิดใหม่ การแก้หน้าจอไม่ต้อง build/flash แต่การแก้การควบคุมบนบอร์ดในไฟล์ C ต้อง build และ flash

## ค่าปรับง่ายที่ต้นไฟล์

| ตัวแปร | ค่าเดิม | ผลเมื่อแก้ |
|---|---|---|
| `$DashboardTitle` | SMART HOME 1.4 … | เปลี่ยนหัวหน้าจอ ไม่เปลี่ยน firmware ของบอร์ด |
| `$LabelWidth` | 22 | เพิ่มเป็น 26 ทำให้คอลัมน์สถานะเริ่มห่างจากชื่ออุปกรณ์ขึ้น |
| `$RefreshMs` | 200 | เปลี่ยนเป็น 500 วาดหน้าจอทุกครึ่งวินาที; ไม่ได้เปลี่ยนความถี่ส่งข้อมูลของบอร์ด |
| `$StaleSeconds` | 4 | เวลาที่ไม่ได้รับข้อมูลครบชุดก่อนขึ้น STALE เช่น 8 จะรอนานขึ้น |

ใช้ค่าบวกสำหรับเวลาและความกว้าง จอแคบเกินไปข้อความจะถูกตัดด้วย ... ให้ขยาย Terminal

## เปลี่ยนชื่อแถว

ใน `Get-DashboardLines()` ตัวอย่างเดิม:

```powershell
$rows += 'FAN'.PadRight($LabelWidth)+$c[10]
```

เปลี่ยนเป็น:

```powershell
$rows += 'VENTILATION FAN'.PadRight($LabelWidth)+$c[10]
```

ชื่อบนหน้าจอจะเปลี่ยน แต่ค่า ON/OFF ยังมาจาก `$c[10]` เหมือนเดิม ควรเปลี่ยนชื่อในรายการ `foreach ($name in ...)` สำหรับตอนรอข้อมูลด้วย หากใส่ภาษาไทยให้บันทึก UTF-8 with BOM เพื่อรองรับ Windows PowerShell 5.1

## เปลี่ยนข้อความสถานะให้เข้าใจง่าย

แทนแถว FAN เดิมด้วย:

```powershell
$fanText = if ($c[10] -eq 'ON') { 'RUNNING' } else { 'STOPPED' }
$rows += 'FAN'.PadRight($LabelWidth)+$fanText
```

จะเปลี่ยน ON/OFF เป็น RUNNING/STOPPED บนหน้าจอเท่านั้น ไม่เปลี่ยนการทำงานของพัดลม

## ย้ายหรือเพิ่มแถว

ย้ายบรรทัด `$rows += ...` ภายในส่วนที่มีข้อมูลแล้ว เพื่อเปลี่ยนลำดับ เช่นย้าย FAN ไว้ต่อจาก BATTERY โดยย้ายเฉพาะบรรทัดแสดงผลและคงการคำนวณตัวแปรไว้ก่อนใช้

เพิ่มค่าปุ่มหมุน ADC หลังแถว LIGHT SENSOR ได้ดังนี้:

```powershell
$rows += 'TARGET KNOB ADC'.PadRight($LabelWidth)+$c[16]
```

จะได้แถวใหม่แสดง ADC ของปุ่มหมุน เพิ่มชื่อในรายการรอข้อมูลด้วย ขยายความสูง Terminal ให้พอ หากเพิ่มหลายแถวให้ปรับเงื่อนไข `$height -lt 25` และข้อความเตือนขนาดขั้นต่ำให้พอกับจำนวนแถวใหม่ หน้าจอเว้นแถวสุดท้ายไว้ป้องกันการเลื่อน

## ตารางข้อมูลที่ใช้แสดง

`$c=$s.Core` เป็นข้อมูลจากบรรทัด BAT ของบอร์ด เริ่มนับ index ที่ 0

| Index | ความหมาย |
|---|---|
| 0 | ระดับแบต 0–9 |
| 1 / 2 / 3 | พลังงานปัจจุบัน / เต็ม / เปอร์เซ็นต์ |
| 4 / 5 | อุณหภูมิที่อ่าน / เป้าหมายแอร์ |
| 6 / 7 | โหมดแอร์ / สถานะแอร์ |
| 8 / 9 | โหมดไฟ / สถานะไฟ |
| 10 / 11 | พัดลม / ECO |
| 12 / 13 | พลังงานชาร์จ / ใช้ ต่อ tick |
| 14 / 15 / 16 | ADC อุณหภูมิ / แสง / ปุ่มหมุน |

`$p=$s.Power`: index 0 สถานะแบต, 1 ชาร์จ units/s, 2 โหลด units/s

`$l=$s.Light`: index 0 ความสว่างที่ปรับทิศแล้ว, 1 คำอธิบาย, 2 จำนวนชุด DMA, 3 ทิศ LDR

อย่าสับสน `$c[12]` ซึ่งเป็นต่อ tick กับ `$p[1]` ซึ่งเป็นต่อวินาที และอย่าเปลี่ยน index เพียงเพื่อให้เลขดูถูกต้อง เพราะจะทำให้แสดงค่าของอุปกรณ์อื่น

## ทำไมทุกแถวอัปเดตพร้อมกัน

`Receive-DashboardText()` รับข้อความลง Buffer แล้วแยกบรรทัด เมื่อเห็น `--- LIVE STATUS ---` จะเริ่ม Pending รับค่าต่อไปจนถึงบรรทัด Brightness และมี Core/Power ครบ จึงเปลี่ยน Snapshot ทั้งชุด `Get-DashboardLines()` สร้างทุกแถวจาก Snapshot เดียวกัน แล้วลูปวาดจอเลื่อน cursor กลับจุดเริ่มและเขียนทั้งชุดครั้งเดียว ไม่ใช้ Write-Host ทีละค่าทุกครั้งที่ UART ส่งมา

ถ้าจะแก้รูปแบบข้อความที่บอร์ดส่ง ต้องแก้ `PrintTelemetry()` ใน `Application/Src/app_energy.c` พร้อม regex ใน `Receive-DashboardText()` ให้ตรงกัน มิฉะนั้น parser อาจไม่รับเฟรมและหน้าจอขึ้น STALE การเปลี่ยนชื่อแถวอย่างเดียวควรแก้เฉพาะส่วนแสดงผล

## ตรวจหลังแก้

```powershell
./live_status.ps1 -SelfTest
./live_status.ps1 -Port COM3
```

SelfTest ตรวจ parser และข้อความสำคัญ หากตั้งใจเปลี่ยนชื่อ/ข้อความที่ทดสอบไว้ ต้องปรับ assertion ใน `Test-Dashboard()` ให้ตรงด้วย โดยยังคงตรวจความถูกต้องของค่าและการรับข้อมูลครบชุด

แถว Firmware และ POLICY มาจากบอร์ดจริง เปลี่ยนหัวหน้าจอเป็น 1.4 อย่างเดียวไม่ได้ทำให้บอร์ดรัน 1.4 แถว 7-SEGMENT แสดงคำสั่งและ GPIO ไม่ใช่ผลอ่านเลขจากหน้าจอจริง
